按那个顺序，投递时要等 4 周以上，而目标岗位是 **AI Agent 开发**，不是 RAG。

四个 JD 的交叉统计（详见对话记录）：

| 要求 | 命中 |
| --- | --- |
| 任务规划 / 编排 | 3/4 |
| **Agent 框架**（LangGraph / LangChain / CrewAI） | **2/4** |
| **MCP / Skills** | **2/4** |

**为什么 `get_clause_detail` 必须做（不是补计划，是补真实缺口）**：

运行数据里 Agent 反复搜「第十五条 合同生效及附件」，**始终拿不到该条正文**，
多数时候返回的是第二十六条，它只能诚实地说"我无法确认"。

它缺的就是「**我已经知道条款号，直接给我全文**」这个能力。

而且现在**实际只有一个主工具**（`list_documents` 很弱），
**真正的工具选择（模糊搜 vs 精确取）从没被考验过** —— 而那才是"任务规划"。

# 第 A 周｜Agent 核心（先把循环手写一遍，再上框架）

**本周目标**：能讲清「Agent 循环到底是什么」，并且能用 LangGraph 实现。
**为什么先手写**：JD2 写着「阅读并理解过框架源码者加分」。
手写一遍 = 读过核心逻辑；只会调 API 的人答不了「LangGraph 帮你做了什么」。

## A1｜工具抽象 + 手写最小 ReAct 循环

- **关键节点（你写）**：一个 `run_agent(question, max_steps)` 循环 ——
  模型输出 → 判断要不要调工具 → 执行 → 把结果塞回消息 → 再问模型 → 直到给出答案或超步数
- **助手提供**：工具 schema 定义、工具注册表的骨架
- **验收**：问「合同什么时候生效」，Agent 自己决定调用检索工具，然后作答
- **对应 JD**：任务规划（3/4）、function calling

## A2｜第二个工具 + **工具选择的观察记录**

> **范围调整**：原计划的 `list_risks` 已删（依赖风险规则库，W3 已砍）。
> 只做 `get_clause_detail`。**但「观察并记录」那一条完整保留 —— 那才是 A2 的产出。**

- **关键节点（你写）**：`get_clause_detail(clause_no, doc_id=None)`
  —— 表达「我已经知道条款号，直接给我全文」
- **必须观察并记录**（不是副产品，是主产品）：
  - 同一个问题，模型选 `search_clauses` 还是 `get_clause_detail`？
  - 会不会**两个都调**，或者**连调两次同一个**？
  - 参数给错时（比如只给条款号、没给 `doc_id`）它怎么反应？
  - 查不到时（条款号不存在）它是重试、换工具，还是编造？
- **验收**：有一个问题能让 Agent 连续调用 2 个不同工具，
  **并且你能说出它为什么这么选**
- **对应 JD**：多工具编排（3/4 命中）、Skills

**为什么这个观察比写工具重要**：工具写出来只是一堆函数；
**"模型在什么情况下会选错"才是你面试能讲的东西** —— 因为那是只有做过的人才有的观察。

## A3｜失败模式：死循环、超步数、工具报错

- **关键节点（你写）**：步数上限 + 终止条件 + 工具异常包装
  （工具抛异常时要变成「给模型的一条 observation」，**不是让整个流程崩**）
- **必须实测并记录**：把工具故意改成报错，看 Agent 怎么反应；把上限设成 1，看它怎么退化
- **验收**：三种失败各有一次真实记录
- **对应 JD**：稳定性（JD4）、工程优化（JD2）

## A4｜LangGraph 重写

- **关键节点（你写）**：`StateGraph` + `add_node` / `add_edge` / `add_conditional_edges`
  + 条件边做「要不要继续调工具」+ 循环
- **助手提供**：State 的 TypedDict 定义、图的结构草图
- **验收**：同一个问题，LangGraph 版本和手写版本结果一致
- **对应 JD**：LangGraph 熟练（2/4）

## A5｜checkpointer + 对比记录

- **关键节点（你写）**：接入 checkpointer，让 Agent 能中断后续跑（多轮对话的基础）
- **核心产出**：**手写循环 vs LangGraph 的对比记录** ——
  各解决了什么、LangGraph 替你做了什么、多出来哪些概念（State / Reducer / Checkpoint）
- **验收**：这段记录直接就是面试答案
- **对应 JD**：JD2「理解框架源码者加分」的替代

# 第 B 周｜MCP + Agent 化 + 可观测性

## B1｜FastMCP server（本周最高 ROI）

- **关键节点（你写）**：`FastMCP` 起一个 server，把检索能力暴露成 `@mcp.tool()`
- 依赖已装：`mcp[cli]==2.2.0`，入口是 `from mcp.server.fastmcp import FastMCP`
- **验收**：任意 MCP 客户端能挂载并调用到这个工具
- **对应 JD**：**MCP / Skills（2/4）**

## B2｜Resources + 多工具

- **关键节点（你写）**：把「文档清单」做成 Resource，再加 2 个 tool
- **注意**：tool 是「模型决定调用」，resource 是「客户端读取」—— 这个区别面试会问
- **对应 JD**：JD3「熟练使用 FastMCP 开发 MCP」

## B3｜第二个 Agent + 人工确认

- **关键节点（你写）**：复核 Agent（读第一份报告，找遗漏和矛盾）；
  以及一个需要人工确认的节点（高风险结论暂停等确认）
- **对应 JD**：多 Agent、HITL

## B4｜故障实验（3 个）

- **你跑并记录**：断网重试、工具超时降级（**降级但不能编造**）、越权拦截
- **对应 JD**：JD4「稳定性」、JD2「定位系统瓶颈」

## B5｜可观测性 + 成本数据

- **关键节点（你写）**：Langfuse 埋点（依赖已装 `langfuse==4.16.0`），
  记录每次 Agent 运行的：步数、工具调用次数、token、延迟
- **核心产出**：**一组成本/延迟数据** —— 这是 JD2「降低成本」和 JD4「优化成本」的直接证据
- **复用**：把 W1 已有的分段耗时（EXP-007 那种对账方法）接到 Agent 层
